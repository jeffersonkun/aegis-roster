# AEGIS (AGS) Command Center — WARDOGS MVP

Интерактивный прототип внутренней панели управления кланом AEGIS (AGS) для WARDOGS.

## Визуальная концепция
- Нейтральная графитовая палитра вместо зелёной темы.
- Брендинг клана AEGIS (AGS).
- Цвета LONESTAR, VALKYRA и MANTICORE используются только для обозначения игровых фракций.

## Что работает в текущем этапе
- Главный экран — состав клана, без матчей, турниров и статистики в навигации.
- Реестр игроков: поиск, фильтры по статусу, боевой роли и назначению старшего состава.
- Добавление и редактирование игрока: игровой ник, Discord ID, статус, боевая роль, назначение, отряд и даты.
- Карточки боевых ролей с описанием и быстрым фильтром по нажатию.
- Отдельные назначения старших: Старший Штурм, Старший Летчик, Старший Медик, Старший Подрывник, Старший Строитель, Старший Танк.
- Экспорт локальных данных в JSON.
- Более крупная системная типографика без загрузки внешних веб-шрифтов.
- Адаптивная вёрстка для телефона и компьютера.

## Важно
Это первая локальная версия. Данные сохраняются в `localStorage` текущего браузера. Они НЕ синхронизируются между офицерами и не защищены серверной авторизацией. Не вносите сюда реальные приватные кадровые заметки.

## Запуск локально
Самый простой способ — открыть `index.html` в браузере. Для некоторых браузерных API удобнее запустить простой сервер:

```bash
python3 -m http.server 8080
```

Затем открыть `http://localhost:8080`.

## Бесплатный статический хостинг
Можно загрузить файлы проекта в отдельный GitHub-репозиторий и включить GitHub Pages (Settings → Pages → Deploy from a branch → main / root). Это даст публично доступную демо-версию, но без общей базы и закрытой авторизации. Не используйте публичную Pages-версию для настоящих внутренних данных.

## Следующий этап для реального использования офицерами
1. Создать Supabase project и таблицы PostgreSQL.
2. Настроить Discord OAuth2 через серверную авторизацию.
3. Добавить серверные проверки прав командира/офицеров.
4. Перенести операции чтения и записи с localStorage в API + базу.
5. Добавить Discord-бота для регистрации на матчи и напоминаний.
6. Включить резервное копирование и проверить восстановление.

## Структура

## Подключение Supabase (общий состав)
1. Откройте `config.js` и вставьте Project URL и Publishable key из Supabase → Project Settings → API Keys. Допускается публичный `sb_publishable_...` или legacy `anon` key. Никогда не вставляйте `service_role`/secret key.
2. Закоммитьте `config.js`, `index.html`, `app.js`, `styles.css` в GitHub. Cloudflare Pages пересоберёт статический сайт автоматически.
3. Войдите под пользователем, чей UUID добавлен в `public.profiles`.
4. Убедитесь, что таблица `public.members` изначально пустая или содержит только реальные записи. Демо-игроки автоматически не импортируются.
5. Создайте отдельного пользователя Supabase Auth для каждого офицера и добавьте соответствующую строку в `public.profiles` с ролью `officer` или `viewer`.

В браузере используется только публичный ключ Supabase. Доступ к таблицам контролируется RLS-политиками. Текущая версия синхронизирует состав игроков; Discord OAuth и Discord-бот не подключены.
